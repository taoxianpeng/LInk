# Windows 平台适配实施计划（v0.3.0，分支 `windows_dev`）

## Context

LInk 目前只有 Linux/X11 后端：面板是 eframe/egui（纯 Rust），画布是 GTK + cairo 的独立进程，两者用 `link-ipc` 的 JSON lines 通信。

Windows 适配的真正障碍不在窗口层，而在**渲染层与 GTK/cairo 的硬绑定**：

- `src/render.rs`（642 行）、`src/cache.rs`、`src/export.rs`、`src/ui/overlay.rs` 全部以 `cairo::Context` 为参数，且依赖 `push_group`/`pop_group_to_source`（原子合成）、`set_device_scale`、`stroke_preserve`/`fill_preserve`、`Operator::Source` 覆盖贴图这几项语义。
- `Cargo.toml` 把 `gtk`/`cairo-rs` 写成无条件依赖，Windows 上无法构建（本机实测 `cargo check` 直接失败）。
- 面板侧基本已跨平台（`settings.rs`/`dialog.rs`/`ipc.rs` 都有 cfg 分支），只剩 `raise_window`、字体路径、`std::process::exit(0)` 三处需处理。

目标：Windows 上用 Win32 分层窗口 + `WM_POINTER` + `BitBlt` 实现与 Linux **功能等价**的画布；渲染逻辑只维护一份，Linux 侧继续用 cairo 后端。

## 零、分支与版本（按你的要求）

- 从当前 `main`（`f58dbbb`）新建分支 **`windows_dev`**，全部改动提交在该分支，不直接动 `main`。
- **版本号保持 `0.3.0` 不变**：不改 `Cargo.toml` 的 `version`、不改 `link-ipc` 的 `0.2.0`、**不改 `PROTOCOL_VERSION`**（命令/事件定义不变）。README 里的「当前版本：0.3.0」保留。

## 一、渲染抽象（核心）

新增 `src/paint/`，把「几何」与「光栅化后端」彻底分开：

- `src/paint/mod.rs`
  - `Path2` / `PathBuilder2`：后端无关路径（`move_to`/`line_to`/`close`/`circle`/`rect`），f64。
  - `Canvas` trait：`save/restore`、`translate/scale/rotate`、`set_color/set_line_width/set_dash`、`fill_path/stroke_path`、`paint`、`clip_rect`、`push_group/pop_group_to_source`、`drop_to_source`。坐标统一为**表面设备像素**。
  - `Surface` trait：`new(width,height)`、`canvas()`、`paint_into(dst, Blend)`、`read_rgba()`/`write_rgba()`（straight RGBA）、`fill()`。
  - `Blend::{Source, Over}`；`new_surface()` 按平台选后端。
- `src/paint/cairo_backend.rs`（`cfg(target_os="linux")`）：`CairoCanvas`/`CairoSurface` 逐方法 1:1 映射现有 cairo 调用；构造时执行一次 `scale(1/device_scale)`，上层坐标恒为设备像素，**取消对 `set_device_scale` 的依赖**（与 `export.rs` 现有 `to_physical_pixels` 路线统一）。
- `src/paint/skia_backend.rs`（`cfg(target_os="windows")`）：`SkiaCanvas`/`SkiaSurface`（tiny-skia `Pixmap`，预乘 RGBA）。
  - `clip_rect` → `subpixmap(IntRect)` + `Transform::pre_translate(-clip.origin)`，零分配裁剪。
  - `push_group`/`pop_group_to_source` → 按裁剪矩形 `clone_rect` 出组位图，组内用 `-clip.origin` 变换，回贴用 `BlendMode::Source` + `draw_pixmap`；**保留 Source 覆盖语义**（README 第 16 条残影回归点）。

改造调用方（只换类型，控制流不变）：
- `src/render.rs`：`&Context` → `&mut dyn Canvas`；`stroke_preserve`/`fill_preserve` → 同一 `Path2` 连续调用；`new_sub_path + arc` → `push_circle`。`smooth_polyline`/Catmull-Rom/端点帽与现有单测原样保留。
- `src/cache.rs`：`ImageSurface` → `Box<dyn Surface>`；按**物理像素**建面，绘制用 `view.to_physical_pixels(scale)`；`paint()` 改为 `surface.paint_into(canvas, Blend::Source)`。
- `src/export.rs`：删除 stride/BGRA/手写反预乘（`write_pixel`/`read_pixel` 的 endian 双份实现整段删除），改用 `Surface::read_rgba`；`ExportError::Cairo` → `ExportError::Paint`；`layer_thumbnail_png` 仍返回 PNG。
- `src/ui/overlay.rs`：`clip_extents()` 改为显式 `clip_hint: Option<RectI>` 参数；`ATOMIC_COMPOSE_MAX_AREA` 判定与原子合成流程保留。
- `src/canvas_app.rs`：`draw()` 参数改 `&mut dyn Canvas`；其余不动。

## 二、Windows 平台后端

新增 `src/platform/win/`（`cfg(target_os="windows")`），在 `src/platform/mod.rs` 按 cfg 接线 `Platform`/`overlay`/`compositor_active`：

- `mod.rs` — `WinPlatform::new()`：`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`（失败回退 `SetProcessDPIAware`）；`EnumDisplayMonitors` + `GetMonitorInfoW` 取主屏物理矩形；`GetDpiForMonitor(MDT_EFFECTIVE_DPI)` 得 scale；`capture_primary()` 委托 `capture.rs`。
- `overlay.rs` — 窗口与消息循环：
  - 样式：`WS_POPUP` + `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`（**不用** `WS_EX_TRANSPARENT`，否则收不到笔事件）。
  - 位图：`CreateDIBSection` 32bpp、`biHeight` 取**负值**（top-down）、预乘 BGRA；`UpdateLayeredWindowIndirect` + `ULW_ALPHA` + `AC_SRC_OVER/AC_SRC_ALPHA`，`prcDirty` 传本帧脏矩形（整屏重绘传 `NULL`）。
  - 穿透：`WM_NCHITTEST` → 穿透开启或落在面板矩形内返回 `HTTRANSPARENT`，否则 `HTCLIENT`（替代 X11 的 XFixes 输入区域，且不需要挖掉面板可见区域）。
  - 面板矩形：`EnumWindows` + `GetWindowTextW` 匹配标题 `LInk`，`GetWindowRect` 换算到覆盖层坐标，每 400 ms 刷新（与 Linux 一致）。
  - IPC：沿用 reader 线程，命令到达用 `PostMessageW(WM_APP+1)` 唤醒消息循环；`stdin` EOF 时 `PostQuitMessage`。
  - 绘制：合并脏区域 → `canvas_app.draw()` → 只把脏矩形 `UpdateLayeredWindowIndirect` 上去。
- `input.rs` — `WM_POINTERDOWN/UPDATE/UP/ENTER/LEAVE/CAPTURECHANGED`：
  - `GetPointerPenInfo` 取 `pressure`（仅 `penMask & PEN_MASK_PRESSURE` 时有效）、`tiltX/tiltY`、`PEN_FLAG_INVERTED|PEN_FLAG_ERASER` 判橡皮。
  - `GetPointerPenInfoHistory` + `historyCount` 补发一帧内的历史点（解决快速书写折线），随后 `SkipPointerFrameMessages`。
  - 启动时 `EnableMouseInPointer(TRUE)`，鼠标统一走 PT_MOUSE 分支（无压感）；`GetKeyState(VK_SHIFT)` → `shift`。
- `capture.rs` — `GetDC(NULL)` + 兼容 DC + `BitBlt(SRCCOPY | CAPTUREBLT)` 抓主屏，读回 DIB 转 straight RGBA；`SetWindowDisplayAffinity` 可选、失败忽略。

`CanvasHost` trait 保持不变，`tests/canvas_app.rs` 的 `MockHost` 无需改动。

## 三、画布进程入口拆分

Cargo 无法按平台切换 `[[bin]]` 路径，改为单入口分发：

- `src/canvas_main.rs` → 仅保留调度：`#[cfg(linux)] #[path="canvas/gtk_main.rs"] mod imp;` / `#[cfg(windows)] #[path="canvas/win_main.rs"] mod imp;`，`fn main() { imp::run(); }`。
- `src/canvas/gtk_main.rs`：现有 `canvas_main.rs` 内容（GTK 装配 + `refresh_input_region_for`）。
- `src/canvas/win_main.rs`：Win32 装配，复用同一个 `CanvasApp`/`CanvasHost`。
- 新增 `src/damage.rs`（lib，纯逻辑）：`DrawScope`/`merge_scope`/`union_rect`/`integer_rect` 上移，两后端共用，现成 3 个单测一并迁移。

## 四、构建与面板

`Cargo.toml`（版本号不动）：

- `gtk`/`cairo-rs` 从无条件依赖移到 `[target.'cfg(target_os = "linux")'.dependencies]`；`gdkx11`/`x11rb` 保持。
- 新增 `[target.'cfg(target_os = "windows")'.dependencies]`：`tiny-skia = "0.12"`、`windows-sys = { version = "0.61", features = ["Win32_Graphics_Gdi", "Win32_UI_WindowsAndMessaging", "Win32_UI_Input_Pointer", "Win32_UI_Input_KeyboardAndMouse", "Win32_UI_HiDpi", "Win32_System_LibraryLoader", "Win32_Graphics_Dwm"] }`。
- `eframe` features 保持（`x11`/`wayland` 在 Windows 上不参与编译）。

`apps/panel/src/main.rs`：

- `install_fonts`：按 `cfg` 分组，Windows 依次尝试 `%WINDIR%\Fonts\msyh.ttc`（egui 0.37 的 `FontData.index` 支持 TTC）→ `msyhl.ttc` → `simhei.ttf` → `simsun.ttc`；Linux 保持原候选。
- `raise_window`：Windows 用 `SetWindowPos(hwnd, HWND_TOPMOST, …, SWP_NOMOVE|NOSIZE|NOACTIVATE|SHOWWINDOW)`；窗口句柄从 `RawWindowHandle::Win32` 取。
- 退出：`Action::Quit` 改为 `self.save_settings_now(); self.client.take(); ctx.send_viewport_cmd(ViewportCommand::Close)`——`std::process::exit(0)` 会绕过 `Drop`，可能留下孤儿画布进程。
- 透明：Windows 上 `with_transparent(false)` + `clear_color` 返回不透明 `PANEL_BG`，规避 WGL composite-alpha 不可靠导致的圆角黑边；Linux 保持现状。

- `examples/probe_perf.rs`、`probe_frame.rs` 改用 paint 抽象；`probe_stroke.rs` 的 cairo 参照线保留在 `cfg(linux)`。

## 验证

1. `git switch -c windows_dev`（从 `f58dbbb`）。
2. `cargo build --workspace`（Windows）。
3. `cargo test --workspace`：`app_state`、`model_layers`、`input_pressure`、`view_geometry`、`xopp_roundtrip`、`canvas_app`、`export_image`、重写后的 `render_surface`/`render_cache` 全绿。
4. `python tools/ipc-smoke.py target/debug/link-ink-canvas`：握手、图层、改名、可见性、白底导出、版本校验。
5. 手动 GUI：`cargo run --release` → 笔/鼠标书写（压感粗细）、图形工具、框选移动/缩放/旋转、图层增删改、Ctrl+Z、F8 穿透后能点到下层窗口、Ctrl+S/O、导出 PNG 与「当前屏幕」、拖动面板时仍可点击。
6. 面板退出后任务管理器确认无残留画布进程。

## 风险与说明

- **Linux 侧本机无法验证**：本机没有 GTK 开发库（无 `pkg-config` / `libgtk-3-dev`），`cairo_backend.rs` 只能做「逐调用 1:1 映射 + 人工复核」。合并前需要你在 Linux 上跑一次 `cargo build --workspace && cargo test`。
- 像素结果不会与 Linux 完全一致（cairo 与 tiny-skia 的 AA 不同），测试改为读 RGBA + 宽松阈值，不做逐字节比较。
- Windows 已知限制（写入 README）：只覆盖主屏；`BitBlt` 抓不到独占全屏/受保护内容；HDR 屏可能偏色；面板为不透明窗口（不做逐像素透明圆角）。
