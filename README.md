# LInk — X11 屏幕标注 / 数位板笔迹软件

在 Linux/X11 主显示器上覆盖一层**完全透明**的画布：用数位板或鼠标在上面写画，
笔迹悬浮于桌面之上；一键切换穿透后，笔和鼠标回到下层应用，笔迹继续显示。
工程文件保存为 Xournal++ 的 `.xopp` 格式，可用 Xournal++ 打开与继续编辑。

当前版本：`0.2.0`（egui 面板 + 原生画布）。目前只实现 Linux/X11 后端，Wayland 与 Windows 只预留了平台边界。


## 架构：egui 面板 + 原生画布（两进程）

界面是 **egui（eframe）** 写的纯 Rust 面板，笔迹画布是一个独立的原生进程
（GTK + cairo）。两者用一行一条 JSON 的协议通信，代码里没有 webview。

```
link-ink-panel (eframe/egui)  ──JSON lines(stdin/stdout)──▶  link-ink-canvas (GTK + cairo)
  工具/颜色/笔宽档位/图层/文件对话框/设置                         全屏透明覆盖层、压感、渲染、xopp、导出
                   共享 crates/link-ipc（纯 DTO，无 GUI 依赖）
```

- 面板是入口：启动时自动拉起同目录下的 `link-ink-canvas`，面板退出画布随之退出（stdin EOF）。
- 画布拥有文档：图层、笔迹、缩略图、xopp 存取、图片导出都在画布进程里完成，
  面板只发命令、收状态。
- 画布是**后创建的全屏置顶窗口**，会盖住面板；解决办法是把画布的 XFixes 输入区域
  设成「整屏 − 面板矩形」（面板可拖动，每 400 ms 重算），点击才落到面板上。

## 构建与运行

系统依赖（Debian/Ubuntu 系）：

```bash
sudo apt install libgtk-3-dev libcairo2-dev pkg-config libx11-dev \
                 libxfixes-dev libxrandr-dev
```

```bash
cargo build --workspace --release   # 产出 target/release/{link-ink-panel, link-ink-canvas}
cargo run --release                 # 启动 egui 面板（默认二进制，会自动拉起画布）
cargo run --release --bin link-ink-canvas   # 只启动画布（通常由面板拉起，调试用）
```

打包时把两个可执行文件放在同一目录即可：面板会先找同目录，其次看 `LINK_CANVAS_BIN`。

> ⚠️ **改完代码请用 `cargo build --workspace`**：`cargo run` 只重建它要运行的那一个二进制，
> 画布可能还是旧的。两个进程靠 `link-ipc` 的协议版本握手，版本对不上时面板会直接提示
> “画布与面板版本不一致”，而不是让命令悄悄失效（改协议时记得同步 +1 `PROTOCOL_VERSION`）。

需要**合成器**（Muffin / Mutter / picom 等）才能正确显示透明窗口；缺失时程序会弹窗警告。
画布只覆盖主显示器，副屏不受影响。

## 快捷键

面板获得焦点时生效（不做全局键盘 grab）：

| 键 | 作用 |
|---|---|
| `P` / `E` | 画笔 / 橡皮擦 |
| `L` / `R` / `O` | 直线 / 矩形 / 椭圆 |
| `S` / `F` | 矩形选择 / 自由套索选择 |
| `Esc` | 清除当前选择 |
| `F8` | 切换穿透 |
| `Ctrl+S` / `Ctrl+O` / `Ctrl+E` | 保存工程 / 打开工程 / 导出图片 |
| `Ctrl+Z` | 撤回上一步（最多 50 步） |

绘制时按住 `Shift` 约束为正方形 / 正圆。笔宽、gamma、最小宽度比例**只影响之后的新笔迹**，
不会回溯修改已提交的笔迹。

## Xournal++ 兼容性

保存格式为 gzip 压缩的 XML（`fileversion="4"`，单页），关键约定：

- 压感笔迹的 `width` 属性恰好 **N 个 token**（N = 点数）：第 1 个是基准笔宽，
  之后是前 N−1 个点的实际宽度；常量宽笔迹只写一个标量。
- 颜色 `#rrggbbaa`；坐标为 `x y` 成对值，单位 pt。
- `<layer>` 顺序即底→顶；图层名写入 `name`。
- Xournal++ 没有原生矩形/椭圆对象，图形以 `tool="pen"` 的闭合笔迹保存（格式限制）。

**已实测**（本机 `xournalpp 1.3.4`）：本程序保存的多图层 + 压感 + 图形样本可被 Xournal++ 正常读取，
颜色、线宽渐变、图层顺序、图形形状均正确。复现方式：

```bash
cargo run --example sample_xopp -- target/verify/link_sample.xopp
gzip -dc target/verify/link_sample.xopp | head -30     # 检查 XML
xournalpp -i target/verify/link_sample.png target/verify/link_sample.xopp
```

加载外部 `.xopp` 时，若含文本、图片、PDF 背景或多页等不支持内容，程序会明确警告，
并**清空当前工程路径**、要求另存，避免覆盖原文件丢数据。

## 导出图片

「导出图片」先选格式与背景，再选保存路径：

- **空白白底**：纯白底 + 笔迹，适合贴进文档。
- **当前屏幕**：真实屏幕内容 + 笔迹。流程是面板先隐藏自己 → 通知画布 → 画布隐藏覆盖层、
  排空事件并 `sync`、等约 150 ms（两帧）→ 抓取主屏像素 → 恢复覆盖层并重新应用输入区域。
  隐藏/恢复由 RAII guard 保证，任何错误路径都不会让覆盖层永久消失。
- 输出尺寸 = 主显示器物理像素，笔迹位置与屏幕上完全一致；不含面板、覆盖层或鼠标指针。
- 导出前会先提交正在绘制的手势，避免最后一笔丢失；导出不改变当前工具与模式。

## 面板交互（egui）

面板采用紧凑布局（宽 300 logical px，高度随内容自动伸缩），只保留高频操作：

- **图标按钮**：工具（画笔/橡皮擦/直线/矩形/椭圆/矩形选择/自由选择）、图层操作（新建/删除/上移/下移）、
  文件操作（打开/保存/导出）、清空当前层，全部是自绘图标（egui `Painter`，不依赖图标字体），
  文字只在 tooltip 里，鼠标悬停才显示。
- **调色板**：12 个预设颜色 + 自定义取色，单行排列，点一下立刻生效，当前颜色用强调色圆环标出。
- **笔宽档位**：细 / 中 / 粗三段选择，右侧显示当前实际 pt 值，悬停可看各档数值。
- **选区操作栏**：有选中笔迹时出现，包含「已选 N」、缩放 `− / +`、独立选区取色、`→ 图层` 下拉和清除按钮。
- **穿透开关**：一颗胶囊开关；开启后鼠标与笔事件交给下层应用，快捷键 F8 可切换。
- **设置窗口**：标题栏齿轮打开，集中放置不常改的参数（三档笔宽的具体数值、压感曲线、最细比例）；
  修改即时下发画布，并在空闲 400 ms 后自动保存。
- **文件对话框在工作线程里弹出**，UI 不会卡住（见下文"开发过程中修掉的问题"）。

## 设置与持久化

笔宽档位、当前档位与压感参数保存在系统配置目录，启动时读取并自动应用到画布，无需每次重设：

- Linux/macOS：`$XDG_CONFIG_HOME/link-ink/settings.json`，未设置时为 `~/.config/link-ink/settings.json`
- Windows：`%APPDATA%\link-ink\settings.json`

```json
{
  "width_presets": [1.0, 2.0, 4.0],
  "width_preset": 1,
  "gamma": 1.0,
  "min_ratio": 0.25
}
```

`width_presets` 依次是细 / 中 / 粗三档的 pt 值，`width_preset` 是当前档位（0/1/2）。
文件缺失、JSON 损坏或数值越界时回退默认值并夹紧到合法范围（笔宽 0.1–20 pt、gamma 0.2–4.0、
最细比例 0–1）。改动采用 400 ms 防抖写入，关闭设置窗口或退出时立即落盘。

## 图层面板（PS 风格）

每一行是 `[眼睛] [缩略图] [名字]`，不显示笔画数量：

- **眼睛**：点击显示/隐藏该图层。隐藏的图层不参与屏幕渲染和图片导出，缩略图会变暗提示。
  可见性只是编辑状态，**不写入 `.xopp`**（Xournal++ 没有这个属性），重新打开工程后所有图层都是可见的。
- **缩略图**：按当前图层内容实时渲染（隐藏时仍然显示内容，只是变暗）。点击打开独立预览窗口，
  窗口按页面比例放大显示该层，内容变化时会自动刷新。
- **名字**：点进输入框直接改，回车或失焦提交；空名字会被拒绝并恢复原名。图层名会写入 `.xopp`。
- 在隐藏图层上落笔时该层会自动显示，避免"画完笔迹凭空消失"。
- **叠放顺序**：列表越靠上 = 图层越靠上（和 Photoshop 一致）。在非顶层书写时，
  草稿也会被上方图层实时遮住，不会"画的时候浮在上面、松手才掉下去"。

实现要点：

1. 缩略图由画布进程渲染成 PNG（base64）随 `state` 事件下发，面板解码成 egui 纹理并按图层 id 复用。
2. 改名用一个小弹窗完成，避免行内输入框与列表刷新互相干扰。
3. 点缩略图打开放大预览窗口，内容变化时自动刷新。

## 选择与编辑（S / F）

- **矩形选择（S）**：拖出矩形选框，笔迹连同笔宽完全落在框内才选中。
- **自由选择（F）**：按住拖出自由路径，松开后闭合为多边形；笔迹需完整落在多边形内。
- 拖动选框时**实时**显示选框区域，并给当前会被选中的笔迹用虚线描边高亮；松开才正式提交选择。
- 选中后画布显示**细实线矩形框**和 8 个手柄（4 个角 + 4 条边的中点）：
  - **框内拖动**：移动整个选区；拖动时原位置笔迹临时提起，只显示跟随指针的副本。
  - **拖边中手柄**：围绕选区中心**等比缩放**，笔宽同步缩放。
  - **拖角手柄**：围绕选区中心旋转。
  - **面板 `− / +`**：同样按 1/1.1、1.1 倍围绕中心缩放，方便精确微调。
  - **改色**：使用选区操作栏里的颜色控件，只改选中笔迹，不影响当前画笔颜色。
  - **换层**：用 `→ 图层` 下拉选择目标层，选中笔迹整体移动过去（目标层隐藏时自动显示）。
  - **清除**：`Esc` 或操作栏的 ×；切换工具、撤回、图层增删/移动、清空图层、打开工程也会清空选择。
- 选中笔迹的边缘始终用虚线标记；选框与手柄用细实线绘制，不遮挡原笔迹。
- 每次移动/缩放/改色/换层都只记一步撤回，`Ctrl+Z` 可完整还原（包括跨图层移动）。
- 选择用图层稳定 id + 笔迹索引定位；选中高亮绘制在所有图层之上，提交后恢复真实叠放顺序。

## 撤回（Ctrl+Z）

- **撤掉最近一笔**：每画一笔（自由笔迹或直线/矩形/椭圆）记一步，`Ctrl+Z` 把那一笔删掉。
- **擦除也能撤**：用橡皮擦掉的笔迹会回到原来的位置和叠放顺序，而不是"撤掉别的笔"。
- **清空图层可撤**：清空后按 `Ctrl+Z` 整层笔迹原样回来。
- **上限 50 步**：超过后丢弃最早的记录；上限常量是 `src/undo.rs` 里的 `UNDO_LIMIT`。
- **画到一半按 Ctrl+Z**：只丢弃当前这一笔的草稿，不会撤掉已提交的笔迹。
- **跨图层正确**：记录用图层的稳定 id 定位，增删/移动图层后依然撤到正确的那一层。
- 打开工程会清空历史（旧记录指向的笔迹已不存在）。

实现上只保存差异（被加或被删的笔迹），不存整份文档快照，所以内存与图层数无关。
测试：`src/undo.rs` 的 5 个单元测试 + `tests/app_state.rs` 的 6 个撤回用例。

## 性能：为什么笔画多了也不会闪

覆盖层每帧都需要重画；如果在每个笔尖事件里都把全部笔迹重新栅格化，4K 屏上会明显掉帧甚至闪烁。
本项目分两层解决：

**1. 已提交笔迹走离屏缓存（`src/cache.rs`）**

每帧只「贴一张图 + 画当前草稿」，不再重新栅格化全部笔迹。缓存失效策略：

| 变化 | 处理 |
|---|---|
| 顶层图层新增笔迹（正常落笔） | 只把新增的那几笔画进缓存，O(1) |
| 非顶层图层新增笔迹 | 整张重建（保证遮挡顺序） |
| 擦除 / 清空 / 图层增删移 / 加载工程 | 整张重建 |
| 打开工程但结构指纹相同 | `invalidate()` 强制重建 |

缓存表面按**物理像素**分配再设设备缩放，绘制仍用逻辑坐标，与屏幕严格 1:1（避免 2x 屏上模糊/错位）。

**2. 草稿用脏矩形重绘（`src/canvas_main.rs`）**

自由笔迹每帧只有最后一小段是新的，所以只排「上一帧草稿区域 ∪ 本帧草稿区域」进重绘队列；
其余像素保持不动，绘制时再从缓存里贴回来。擦除会整条删笔迹，脏区域无法预知，此时整屏重绘。

本机实测（4384×2466 @2x，24 点变宽笔迹）：

| 场景 | 100 笔 | 1000 笔 | 3000 笔 |
|---|---|---|---|
| 旧：每帧清屏 + 重画全部笔迹 | 10.5ms | 35.5ms | 71.9ms |
| 新：整屏贴缓存（图层操作等全屏刷新） | 14.4ms | 11.5ms | 8.5ms |
| 新：正常书写一帧（脏矩形） | 0.01ms | 0.01ms | 0.01ms |
| 缓存重建（擦除/切层时一次） | 3.7ms | 35.4ms | 72.7ms |

即正常书写时每帧只处理笔尖附近几百×几百像素，与总笔画数基本无关。

另外图层缩略图只在图层内容真正变化时刷新（此前每个指针事件都会重画整层笔迹，是第二个闪烁源）。

**3. 一帧的绘制是原子的**

即使每帧只要 0.3ms，「先把草稿区域贴成缓存（等于擦掉草稿）、再重画草稿」这两步之间如果被合成器
采样，屏幕上仍会看到笔迹瞬间缺失——笔画越长、这一帧耗时越久越明显。现在用 cairo 的
`push_group` 把「贴缓存 + 画草稿」合成到一个离屏组，最后一次性贴到窗口；只有整屏重绘
（图层操作、导出恢复，非连续动作）才退回直接绘制，避免多分配一张 43MB 中间表面。

实测（窗口像素级采样，5991 次/条长笔迹、5857 次/条模拟笔迹）**未出现任何半成品帧**。

## 笔迹平滑

快速书写时 GDK 每秒只给几十个采样点，而渲染器是在采样点之间连**直线**——所以手快时会看到明显折痕。
现在变宽笔迹先用**向心 Catmull-Rom**（alpha = 0.5）按 1.5pt 自适应加密再生成轮廓：

- 曲线经过每个原始采样点，不会像 B 样条那样把笔迹「削圆」；
- 向心参数化避免均匀参数化在急转处过冲、自交；
- 线宽沿每段线性插值，粗细过渡自然。

> 已知边界：平滑只作用于变宽（压感）笔迹。常量宽笔迹同时包含图形工具（矩形/直线/椭圆），
> 若统一平滑会把矩形圆角磨掉，所以鼠标画出的自由笔迹仍是折线；用数位板不受影响。

## 架构与平台边界

```text
【画布进程 link-ink-canvas】
数位板/鼠标 ─► platform/x11（GDK 事件 → InputEvent）─► canvas_app（IPC 命令 + 状态机）
                                                         ├─ app / model / view
                                                         ├─ ui/overlay（绘制编排）─► Cairo
                                                         ├─ xopp / export（纯逻辑）
                                                         └─ ipc（link-ipc DTO，stdin/stdout）

【面板进程 link-ink-panel】
egui 界面 ─► ipc 客户端（子进程 stdin/stdout）─► 同样的 link-ipc DTO
```

- X11 专属代码（XFixes 输入区域、XGetImage 截图、XRandR 几何、合成器检测、XID）**只存在于
  `src/platform/x11/`**。
- `src/platform/mod.rs` 用 `pub use x11::… as Platform` 暴露当前后端；`main.rs`、`ui/`、

## 开发过程中修掉的问题（回归提示）

这些是 GUI 实测才暴露、纯逻辑测试覆盖不到的坑，改动相关代码时请留意
（第 1/2/4 条属于已删除的 v0.1 GTK 面板，保留作为历史记录）：

1. **对话框不显示内容**：GTK3 控件默认隐藏，`run()` 前必须 `show_all()`，否则自定义的格式/背景选项全部不可见。
2. **对话框关不掉**：`gtk_dialog_run()` 期间会拦截 delete-event，返回后只调 `close()` 窗口仍留在屏幕上，会被「导出当前屏幕」拍进图片；必须 `hide()` + `destroy()`（见 `dismiss_dialog`）。
3. **保存工程 panic**：把 `state.borrow()` 写在 `match` 判别式里，其临时借用活到整个 match 分支，分支内再 `borrow_mut()` 直接 `RefCell already borrowed` 崩溃（GTK 回调中 panic = 进程 abort）。判别式必须先用 `let` 绑定。
4. **图层列表空白**：窗口显示后动态 `add` 的 `ListBoxRow` 默认隐藏，必须 `row.show_all()`。
5. **图层笔数不刷新**：列表标签含笔数，落笔/擦除后需要用结构指纹触发重建（见 `structure_hash`）。
6. **偶发一笔特别粗**：笔迹的 `variable` 曾由「起笔事件是否带压感轴」唯一决定；起笔事件偶尔不带压感轴时，整笔会退化成常量满宽（`base_width_pt`，本例 3.7pt，比周围 1–2pt 的笔迹粗一倍）。
   现在：缺少压感轴的事件沿用上一次读数（不再回退到 1.0 满宽），且后续事件一旦带回压感就把整笔升级为变宽笔迹并回填已有点；
   若整笔始终没有压感读数则按常量宽绘制并 `log::warn!` 提示（便于定位驱动问题）。回归测试见 `tests/app_state.rs` 的三个以 `pressure` 命名的用例。
7. **笔画多时书写闪烁**：每帧「清屏 + 重画全部笔迹」在 4K 上要 33ms/帧（1000 笔），屏幕上会看到画面短暂变空。
   现在走离屏缓存 + 脏矩形重绘（见上文「性能」），并且缩略图不再随指针事件重画。
   改动渲染链路时请保持 `tests/render_cache.rs` 里的「缓存绘制结果 == 全量重绘结果」这一不变量。
8. **快速书写有折痕**：采样点稀疏 + 直线连接。现在渲染前用向心 Catmull-Rom 加密（见「笔迹平滑」），
   单元测试在 `src/render.rs` 的 `smooth_tests`，约束了端点保持、折角不过冲、退化输入不出 NaN。
9. **长笔迹仍会闪**：单帧内「擦掉草稿 → 重画草稿」不是原子的，会被合成器采到中间态。
   现在小区域走 cairo group 原子合成（见「性能」第 3 点）；改这段逻辑时不要拆开这两步。
10. **点「保存工程」后窗口卡死（v0.2 egui 面板）**：文件对话框若在 UI 线程里同步调用，
    egui 的更新循环会被一直阻塞，窗口管理器几秒后判定 “not responding”。
    现在对话框在工作线程里弹（Linux 优先 zenity/kdialog，其次 rfd portal），
    主线程每帧非阻塞轮询结果（`apps/panel/src/dialog.rs`）。不要在 `update()` 里调阻塞式对话框。
11. **撤回条目要按图层 id 而不是索引定位**：只记索引的话，新建/删除/移动图层后
    再按 Ctrl+Z 会撤到别的层上，甚至删错笔迹。`Edit` 里存的是 `Layer::id`（不写进 xopp、
    不参与相等比较），撤回时先按 id 找层，找不到就跳过该条继续往前。
12. **写字时笔迹闪烁（v0.2 画布进程）**：脏矩形虽然算对了（10–20 px），但 GTK 在合成器的
    透明窗口上交给 `draw` 处理器的**裁剪区是整个窗口**，于是每个笔尖事件都变成整屏重绘
    （270 万 px²，约 6–7ms），"擦掉草稿 → 重画草稿"的间隙被合成器采到，看起来就是闪烁。
    现在把脏矩形自己记下来，在 `ui::overlay::draw` 里按它 `clip()`，强制走原子合成分支：
    实测帧裁剪面积 ~300–60000 px²、每帧 0.06–0.25ms。整屏重绘的三处入口必须先清掉这个提示。
13. **`Ctrl+Z` 没反应、日志刷 `unknown variant undo`**：面板已经发出 `undo`，但磁盘上的
    画布还是旧版本（`cargo run --release` 只重建了面板，`link-ink-canvas` 停留在上一次构建）。
    旧画布解析不了新命令，只能打一行 warn 然后丢弃，界面上看起来就是"按键没反应"。
    现在两边握手时比对 `PROTOCOL_VERSION`，不一致就直接弹提示让用户 `cargo build --workspace`。
    **改动 `Command`/`Event` 变体时必须把 `PROTOCOL_VERSION` +1。**
14. **在非顶层书写时笔迹浮在最上面**：草稿是每帧单独画的（不在缓存里），早先直接画在
    所有图层之上，所以在上层有笔迹的情况下，在下层书写会看到笔迹盖住上层，提交后才跳回正确位置。
    现在草稿画完后再把**当前层之上**的笔迹盖回来（`render::draw_layers_above`），
    并按本帧脏矩形的包围盒裁剪，只有相交的笔迹才重画（实测书写帧仍是 0.15ms）。
    回归测试：`tests/render_cache.rs::draft_on_lower_layer_is_covered_by_upper_layers`。
15. **点图层名选不中图层**：名字区域几乎盖满整行，且只处理了双击改名，单击被它吃掉。
    现在单击 = 选中，双击 = 选中并改名。
16. **矩形/椭圆/直线拖动时一片残影**：两个原因叠加。
    其一，离屏组最后用 `Operator::Over` 贴回窗口，而组里没有笔迹的地方是透明的，
    `Over` 不会覆盖这些像素，上一帧的图形就留在屏幕上（自由笔迹一直向外长、新旧完全重叠，
    所以从来没人发现）。**小区域原子合成的最后一步必须用 `Source`**。
    其二，`pending_draw` 是覆盖而不是累加，GTK 把多个指针事件合并成一次绘制时只保留了
    最后一个矩形，之前那些区域根本没被重绘。现在用 `DrawScope` 做并集合并，
    整屏重绘的请求优先级最高。回归测试：`tests/render_cache.rs` 的
    `shape_preview_does_not_leave_ghosts_between_frames`、`src/canvas_main.rs` 的
    `draw_scope_tests`。
17. **全屏覆盖层吞掉面板点击**：画布是后创建的全屏置顶窗口，压在面板上面；窗口管理器
    （Cinnamon/Muffin）会忽略 `ConfigureWindow(Above)` 与 `_NET_RESTACK_WINDOW`，甚至忽略
    `ViewportCommand::Focus` 的抬升。真正的解法是把画布的 XFixes 输入区域设成
    「整屏 − 面板矩形」，并且**顶层窗口和 DrawingArea 子窗口都要设置**，每 400 ms 重算一次。
    改动 `refresh_input_region_for`（`src/canvas_main.rs`）时务必保持这两点。
