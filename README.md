# LInk — X11 屏幕标注 / 数位板笔迹软件

在 Linux/X11 主显示器上覆盖一层**完全透明**的画布：用数位板或鼠标在上面写画，
笔迹悬浮于桌面之上；一键切换穿透后，笔和鼠标回到下层应用，笔迹继续显示。
工程文件保存为 Xournal++ 的 `.xopp` 格式，可用 Xournal++ 打开与继续编辑。

当前版本：`0.1.0`，仅实现 Linux/X11 后端（Wayland 与 Windows 只预留了平台边界）。

## 功能

| 能力 | 状态 | 说明 |
|---|---|---|
| 透明覆盖层 | ✅ | 主屏一层 RGBA 透明窗口，桌面正常可见；工具窗独立置顶 |
| 鼠标 / 数位笔穿透 | ✅ | XFixes 输入区域置空，笔迹保留；工具窗仍可操作（F8 切换） |
| 压感笔迹 | ✅ | XInput2 → GDK 压感轴归一化；笔宽 / gamma / 最小宽度比例三参数可调 |
| 橡皮擦 | ✅ | 整笔擦除，仅作用于当前图层 |
| 图形工具 | ✅ | 直线、矩形、椭圆；Shift 约束正方形 / 正圆；实时预览 |
| 多图层 | ✅ | PS 风格面板：眼睛显示/隐藏、行内缩略图、可编辑图层名、新建 / 删除 / 上移 / 下移 / 选择；新笔迹只写入当前层 |
| 图层缩略图 | ✅ | 每行一个缩略图，随内容变化**只重绘不重建**；点击打开放大预览窗口 |
| 保存 / 打开工程 | ✅ | `.xopp`（gzip XML），保留颜色、线宽、压感、图层与顺序 |
| 导出图片 | ✅ | PNG / JPEG，背景可选「空白白底」或「当前屏幕」 |
| 撤销 / 重做 | ❌ | 本期未实现 |
| Wayland / Windows 后端 | ❌ | 仅做边界预留，见下文 |

## 构建与运行

系统依赖（Debian/Ubuntu 系）：

```bash
sudo apt install libgtk-3-dev libcairo2-dev pkg-config libx11-dev \
                 libxfixes-dev libxrandr-dev
```

```bash
cargo build --release
cargo run --release          # 或直接运行 target/release/link-ink
```

需要**合成器**（Muffin / Mutter / picom 等）才能正确显示透明窗口；缺失时程序会弹窗警告。
画布只覆盖主显示器，副屏不受影响。

## 快捷键

工具窗获得焦点时生效（不做全局键盘 grab）：

| 键 | 作用 |
|---|---|
| `P` / `E` | 画笔 / 橡皮擦 |
| `L` / `R` / `O` | 直线 / 矩形 / 椭圆 |
| `F8` | 切换穿透 |
| `Ctrl+S` / `Ctrl+O` / `Ctrl+E` | 保存工程 / 打开工程 / 导出图片 |

绘制时按住 `Shift` 约束为正方形 / 正圆。笔宽、gamma、最小宽度比例**只影响之后的新笔迹**，
不会回溯修改已提交的笔迹。

## Xournal++ 兼容性

保存格式为 gzip 压缩的 XML（`fileversion="4"`，单页），关键约定：

- 压感笔迹的 `width` 属性恰好 **N 个 token**（N = 点数）：第 1 个是基准笔宽，
  之后是前 N−1 个点的实际宽度；常量宽笔迹只写一个标量。
- 颜色 `#rrggbbaa`；坐标为 `x y` 成对值，单位 pt。
- `<layer>` 顺序即底→顶；图层名写入 `name`。
- Xournal++ 没有原生矩形/椭圆对象，图形以 `tool="pen"` 的闭合笔迹保存（格式限制）。

**已实测**（本机 `xournalpp 1.3.4`）：本程序保存的多图层 + 压感 + 图形样本可被 Xournal++ 正常读取，
颜色、线宽渐变、图层顺序、图形形状均正确。复现方式：

```bash
cargo run --example sample_xopp -- target/verify/link_sample.xopp
gzip -dc target/verify/link_sample.xopp | head -30     # 检查 XML
xournalpp -i target/verify/link_sample.png target/verify/link_sample.xopp
```

加载外部 `.xopp` 时，若含文本、图片、PDF 背景或多页等不支持内容，程序会明确警告，
并**清空当前工程路径**、要求另存，避免覆盖原文件丢数据。

## 导出图片

「导出图片」先选格式与背景，再选保存路径：

- **空白白底**：纯白底 + 笔迹，适合贴进文档。
- **当前屏幕**：真实屏幕内容 + 笔迹。流程是隐藏覆盖层与工具窗 → 排空 GTK 事件并
  `sync` → 等约 150 ms（两帧）→ 抓取主屏像素 → 恢复窗口并重新应用穿透区域。
  隐藏/恢复由 RAII guard 保证，任何错误路径都不会让覆盖层永久消失。
- 输出尺寸 = 主显示器物理像素，笔迹位置与屏幕上完全一致；不含工具窗、覆盖层或鼠标指针。
- 导出前会先提交正在绘制的手势，避免最后一笔丢失；导出不改变当前工具与模式。

## 工具窗交互

- **图标按钮**：工具（画笔/橡皮擦/直线/矩形/椭圆）、图层操作（新建/删除/上移/下移）、
  文件操作（打开/保存/导出）、清空当前层，全部是图标按钮，文字只在 tooltip 里，鼠标悬停才显示。
  主题里没有"画笔/橡皮"的通用符号，这五个工具图标是用 cairo 自绘的（跟随主题前景色，选中态用主题高亮）。
- **调色板不再弹确认框**：12 个预设颜色点一下立刻换色并立即生效；当前颜色用深色描边标出。
  只有需要精确取色时才点末尾的自定义按钮，那时才会弹出取色对话框。

## 图层面板（PS 风格）

每一行是 `[眼睛] [缩略图] [名字]`，不显示笔画数量：

- **眼睛**：点击显示/隐藏该图层。隐藏的图层不参与屏幕渲染和图片导出，缩略图会变暗提示。
  可见性只是编辑状态，**不写入 `.xopp`**（Xournal++ 没有这个属性），重新打开工程后所有图层都是可见的。
- **缩略图**：按当前图层内容实时渲染（隐藏时仍然显示内容，只是变暗）。点击打开独立预览窗口，
  窗口按页面比例放大显示该层，内容变化时会自动刷新。
- **名字**：点进输入框直接改，回车或失焦提交；空名字会被拒绝并恢复原名。图层名会写入 `.xopp`。
- 在隐藏图层上落笔时该层会自动显示，避免"画完笔迹凭空消失"。

实现上有两个容易踩的点：

1. 图层行里的按钮/输入框回调会触发列表重建，如果在自己信号处理里销毁控件会进入
   "边派发事件边析构"的状态，所以刷新都通过 `glib::idle_add_local_once` 延后一轮。
2. 重建列表会销毁正在编辑的输入框；若调用方此时还持有 `state` 的借用，输入框的 focus-out
   回调再借用就会 panic。因此 `StatusHandle::refresh_state` 先在短借用内算好是否重建，
   释放借用后再重建；改名/切可见性则直接同步结构指纹、就地更新，不触发重建。
3. **落笔时面板会闪**：早先只要笔数变化就重建整个列表（删掉所有行再加回来）。
   现在把指纹拆成「结构」（图层数/顺序/名字/可见性 → 才重建）和「内容」（每层笔数 → 只让
   列表重画缩略图），落笔/擦除时控件树完全不动，实测连续画 15 笔、窗口像素采样 67927 次，
   选中行从未消失。

## 性能：为什么笔画多了也不会闪

覆盖层每帧都需要重画；如果在每个笔尖事件里都把全部笔迹重新栅格化，4K 屏上会明显掉帧甚至闪烁。
本项目分两层解决：

**1. 已提交笔迹走离屏缓存（`src/cache.rs`）**

每帧只「贴一张图 + 画当前草稿」，不再重新栅格化全部笔迹。缓存失效策略：

| 变化 | 处理 |
|---|---|
| 顶层图层新增笔迹（正常落笔） | 只把新增的那几笔画进缓存，O(1) |
| 非顶层图层新增笔迹 | 整张重建（保证遮挡顺序） |
| 擦除 / 清空 / 图层增删移 / 加载工程 | 整张重建 |
| 打开工程但结构指纹相同 | `invalidate()` 强制重建 |

缓存表面按**物理像素**分配再设设备缩放，绘制仍用逻辑坐标，与屏幕严格 1:1（避免 2x 屏上模糊/错位）。

**2. 草稿用脏矩形重绘（`src/main.rs`）**

自由笔迹每帧只有最后一小段是新的，所以只排「上一帧草稿区域 ∪ 本帧草稿区域」进重绘队列；
其余像素保持不动，绘制时再从缓存里贴回来。擦除会整条删笔迹，脏区域无法预知，此时整屏重绘。

本机实测（4384×2466 @2x，24 点变宽笔迹）：

| 场景 | 100 笔 | 1000 笔 | 3000 笔 |
|---|---|---|---|
| 旧：每帧清屏 + 重画全部笔迹 | 10.5ms | 35.5ms | 71.9ms |
| 新：整屏贴缓存（图层操作等全屏刷新） | 14.4ms | 11.5ms | 8.5ms |
| 新：正常书写一帧（脏矩形） | 0.01ms | 0.01ms | 0.01ms |
| 缓存重建（擦除/切层时一次） | 3.7ms | 35.4ms | 72.7ms |

即正常书写时每帧只处理笔尖附近几百×几百像素，与总笔画数基本无关。

另外工具窗缩略图只在图层内容真正变化时刷新（此前每个指针事件都会重画整层笔迹，是第二个闪烁源）。

**3. 一帧的绘制是原子的**

即使每帧只要 0.3ms，「先把草稿区域贴成缓存（等于擦掉草稿）、再重画草稿」这两步之间如果被合成器
采样，屏幕上仍会看到笔迹瞬间缺失——笔画越长、这一帧耗时越久越明显。现在用 cairo 的
`push_group` 把「贴缓存 + 画草稿」合成到一个离屏组，最后一次性贴到窗口；只有整屏重绘
（图层操作、导出恢复，非连续动作）才退回直接绘制，避免多分配一张 43MB 中间表面。

实测（窗口像素级采样，5991 次/条长笔迹、5857 次/条模拟笔迹）**未出现任何半成品帧**。

## 笔迹平滑

快速书写时 GDK 每秒只给几十个采样点，而渲染器是在采样点之间连**直线**——所以手快时会看到明显折痕。
现在变宽笔迹先用**向心 Catmull-Rom**（alpha = 0.5）按 1.5pt 自适应加密再生成轮廓：

- 曲线经过每个原始采样点，不会像 B 样条那样把笔迹「削圆」；
- 向心参数化避免均匀参数化在急转处过冲、自交；
- 线宽沿每段线性插值，粗细过渡自然。

> 已知边界：平滑只作用于变宽（压感）笔迹。常量宽笔迹同时包含图形工具（矩形/直线/椭圆），
> 若统一平滑会把矩形圆角磨掉，所以鼠标画出的自由笔迹仍是折线；用数位板不受影响。

## 架构与平台边界

```text
数位板/鼠标 ─► platform（GDK 事件 → InputEvent）─► app（纯状态机）
                                                    ├─ model / view / render
                                                    ├─ ui/overlay（绘制编排）─► Cairo
                                                    ├─ ui/toolbar（GTK 控件）
                                                    └─ xopp / export（纯逻辑）
```

- X11 专属代码（XFixes 输入区域、XGetImage 截图、XRandR 几何、合成器检测、XID）**只存在于
  `src/platform/x11/`**。
- `src/platform/mod.rs` 用 `pub use x11::… as Platform` 暴露当前后端；`main.rs`、`ui/`、
  `model/view/render/input/xopp/export` 都不出现 X11 类型。审计命令：

  ```bash
  grep -rnE "x11rb|gdkx11|X11Platform|std::os::unix|XGetImage|XFixes" src \
    --include='*.rs' | grep -vE '^src/platform/(x11/|mod\.rs)'
  # 应无输出
  ```

- 接入 Windows 时新增 `src/platform/win/{mod,overlay,input,capture}.rs`，并在
  `platform/mod.rs` 里按 `cfg` 切换 `Platform` 别名即可；纯逻辑层不需要改动。
  对应关系：透明层 → `WS_EX_LAYERED` + `UpdateLayeredWindow`；穿透 → `WM_NCHITTEST` 返回
  `HTTRANSPARENT`；压感 → `WM_POINTER` + `GetPointerPenInfo`；截图 → `BitBlt`。
- 接入 Wayland 需要替换的不止两个函数：layer-shell 覆盖层、tablet-v2 压感、
  点击穿透语义、portal/wlr-screencopy 截图，属于独立里程碑。

## 开发过程中修掉的问题（回归提示）

这些是 GUI 实测才暴露、纯逻辑测试覆盖不到的坑，改动相关代码时请留意：

1. **对话框不显示内容**：GTK3 控件默认隐藏，`run()` 前必须 `show_all()`，否则自定义的格式/背景选项全部不可见。
2. **对话框关不掉**：`gtk_dialog_run()` 期间会拦截 delete-event，返回后只调 `close()` 窗口仍留在屏幕上，会被「导出当前屏幕」拍进图片；必须 `hide()` + `destroy()`（见 `dismiss_dialog`）。
3. **保存工程 panic**：把 `state.borrow()` 写在 `match` 判别式里，其临时借用活到整个 match 分支，分支内再 `borrow_mut()` 直接 `RefCell already borrowed` 崩溃（GTK 回调中 panic = 进程 abort）。判别式必须先用 `let` 绑定。
4. **图层列表空白**：窗口显示后动态 `add` 的 `ListBoxRow` 默认隐藏，必须 `row.show_all()`。
5. **图层笔数不刷新**：列表标签含笔数，落笔/擦除后需要用结构指纹触发重建（见 `structure_hash`）。
6. **偶发一笔特别粗**：笔迹的 `variable` 曾由「起笔事件是否带压感轴」唯一决定；起笔事件偶尔不带压感轴时，整笔会退化成常量满宽（`base_width_pt`，本例 3.7pt，比周围 1–2pt 的笔迹粗一倍）。
   现在：缺少压感轴的事件沿用上一次读数（不再回退到 1.0 满宽），且后续事件一旦带回压感就把整笔升级为变宽笔迹并回填已有点；
   若整笔始终没有压感读数则按常量宽绘制并 `log::warn!` 提示（便于定位驱动问题）。回归测试见 `tests/app_state.rs` 的三个以 `pressure` 命名的用例。
7. **笔画多时书写闪烁**：每帧「清屏 + 重画全部笔迹」在 4K 上要 33ms/帧（1000 笔），屏幕上会看到画面短暂变空。
   现在走离屏缓存 + 脏矩形重绘（见上文「性能」），并且缩略图不再随指针事件重画。
   改动渲染链路时请保持 `tests/render_cache.rs` 里的「缓存绘制结果 == 全量重绘结果」这一不变量。
8. **快速书写有折痕**：采样点稀疏 + 直线连接。现在渲染前用向心 Catmull-Rom 加密（见「笔迹平滑」），
   单元测试在 `src/render.rs` 的 `smooth_tests`，约束了端点保持、折角不过冲、退化输入不出 NaN。
9. **长笔迹仍会闪**：单帧内「擦掉草稿 → 重画草稿」不是原子的，会被合成器采到中间态。
   现在小区域走 cairo group 原子合成（见「性能」第 3 点）；改这段逻辑时不要拆开这两步。
